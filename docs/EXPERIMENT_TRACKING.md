# Experiment tracking

We record every model we tried, with its settings and results, so any number in the report can be traced back.

| Method | Where | Needs MLflow? |
|---|---|---|
| **MLflow** | `mlflow.db` and `mlartifacts/` (created locally by the script) | yes |
| **CSV log** | `outputs/results/experiment_log.csv` (committed to the repository) | no |
| **Table below** | generated by the same script | no |

## What is recorded

- **One run per candidate model** (5 runs): model settings as parameters (for example 300 trees, learning rate
  0.05), the data split and seed, and the validation metrics (ROC-AUC, PR-AUC, recall, precision, F1, accuracy, Brier score).
- **One run for the final model**: the held-out test metrics, the confusion matrix counts, the decision
  threshold (0.51), the risk-tier cut points (0.42 and 0.60), how many success criteria were met (5 of 6), and
  the files `model_metadata.json` and `notebook_results.json`, the figures and the model file as artifacts.

The script reads the notebook's saved results; it does **not** retrain anything.

## How to run it and look at the results

```
python -m pip install -r requirements-mlflow.txt
python scripts/log_experiments_mlflow.py
mlflow ui --backend-store-uri sqlite:///mlflow.db
```
Then open <http://localhost:5000> (the first start can take up to a minute). Click the experiment
`diabetic-readmission-30d`. Tick the runs and press *Compare* to see them side by side.

## Notes

- Validation rows are used to choose the model; the test row is looked at once, for the final model only.
- The logistic baseline's validation ROC-AUC reads 0.6670 here (from our independent re-run) and 0.6673 in the
  report (from the group's Colab run). The difference is in the fourth decimal and comes from numerical details
  of the solver; every other number is identical. See the README's reproducibility section.
